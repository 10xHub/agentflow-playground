# Playground Demo Mode Implementation Plan (Sprints 1 and 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public link (`/demo`) that opens the 10xGraph Playground on a pre-recorded support agent. Every screen is filled with real data recorded from a real 10xGraph server, and the demo makes no LLM or backend calls, so it costs nothing to serve and can't be abused.

**Architecture:** A one-time recording run against a real `10xgraph api` (Postgres + Redis + Qdrant, one real model) saves the raw client responses to a JSON fixture. In demo mode, `getTenxGraphClient()` returns a `DemoClient` that answers the same ~23 client methods from that fixture and replays stream chunks with their recorded timing. Because every page already reads data through `getTenxGraphClient()`, pages work unchanged. A thin positioning layer (banner, per-screen callouts, source viewer, CTA) sits on top.

**Tech Stack:** React 19, Vite 6, Redux Toolkit, Vitest + Testing Library (happy-dom), `10xgraph-client` ^0.6.0 in Node for the recorder, Python 3.12 + `10xgraph` + `10xgraph-api` for the demo agent.

**Spec:** Decisions made with the maintainer on 2026-10-15 (no separate spec doc):
1. Showcase without AI cost: the demo replays recorded runs; visitors never trigger a model call.
2. The entry is a demo routing link; arriving through it puts the playground into demo mode.
3. The demo showcases the positioning in `POSITIONING.md` (root of the monorepo), led by pillars 1 and 2.
4. Memory, threads, traces, evals, graph and tools are all populated with data visitors can inspect and verify.
5. WebSocket stays "coming soon" (next release).

## Global Constraints

- In demo mode the browser makes zero requests to any agent backend. Static assets and analytics only.
- Demo mode never writes `10xgraph.settings`, `10xgraph.connections` or `10xgraph.threads` in localStorage. The flag lives in sessionStorage key `10xgraph.demo`.
- Fixture data comes only from `demo/record.mjs` output. Never hand-edit recorded responses. Human-written copy (titles, callouts, chip labels) lives in `demo/scenarios/*.json` and `src/lib/demo/callouts.js`.
- Every demo screen shows the "Recorded demo" banner.
- Fixtures load through dynamic `import()`, so non-demo visitors download none of it.
- Versions: `10xgraph-client` ^0.6.0, `10xgraph-api` >= 0.7.0, `10xgraph` >= 0.10.0.
- The crash/resume scenario needs `PgCheckpointer`. Only `PgCheckpointer` and `InMemoryCheckpointer` implement the tool ledger, and `SqliteCheckpointer` does not.
- Copy rules from `POSITIONING.md`: spell it "10xGraph" in prose; no invented numbers; no em dashes, hype words or exclamation marks; never lead with table stakes (ReAct loop, multi-provider, MCP); never claim per-tool permissions. Every claim in a callout must be visible in the recorded data on that screen.
- WebSocket mode stays `soon: true` in `src/pages/chat/components/chat-header.jsx`.
- The executor does not commit. Each task ends at a checkpoint where the maintainer reviews and commits.

## Review Focus

1. **A visitor with a real saved connection opens `/demo`, then exits.** Their saved connections, active settings and thread cache are byte-for-byte unchanged, and the next page load reconnects to their own server. (Test in Task 4.)
2. **A visitor clicks Stop during a replay.** No further chunks render, the turn ends as "stopped", and the next prompt chip works. (Test in Task 5.)
3. **A visitor opens `/demo/does-not-exist`.** They land in the default scenario, not a blank page or an error. (Test in Task 3.)
4. **A visitor reloads `/memory` while in demo mode.** The tab stays in demo mode and the data comes back. They are not bounced to the connect page or shown "not connected". (Test in Task 4.)
5. **A visitor searches memory for a query that wasn't recorded.** They get keyword matches clearly labeled as such, never an error. (Test in Task 6.)

**Additions beyond the plan**

- `main.jsx` loads the fixture before the first render in a demo tab, so a hard reload on any screen works.
- Entering or leaving the demo dispatches `demoSwitched` (`src/store/app-actions.js`), which re-initializes every Redux slice, and abandons any in-flight run first (`abortActiveRun`), so a replay cut off mid-stream writes nothing. Every way out uses it: the banner's Exit, Settings > Disconnect, and connecting to a real server from the connection menu. Re-verify inside the demo re-probes the recording. Client tools, like threads, are never read or written in demo mode.

- The "View agent source" sheet and the source are lazy chunks; the main bundle is unchanged (513 KB gzip).
- The Memory screen no longer shows fake vector bars, a hardcoded "1536 dims" label or a dead Edit button, and `null` metadata values render correctly. The unused mock data in `src/pages/memory/data.js` is gone.

```python
# demo/agent/payments.py
import json
import os
import uuid
from pathlib import Path


class Payments:
    """Refunds issued by the demo agent, stored outside the checkpointer on purpose."""

    def __init__(self) -> None:
        self.path = Path(os.environ.get("DEMO_PAYMENTS_DB", "payments.json"))

    def _read(self) -> list[dict]:
        return json.loads(self.path.read_text()) if self.path.exists() else []

    def add_refund(self, order_id: str, amount: float) -> dict:
        refund = {"refund_id": f"rf_{uuid.uuid4().hex[:8]}", "order_id": order_id, "amount": amount}
        self.path.write_text(json.dumps([*self._read(), refund]))
        return refund

    def refunds_for(self, order_id: str) -> list[dict]:
        return [r for r in self._read() if r["order_id"] == order_id]
```

```js
// src/lib/demo/demo-mode.js
// Demo mode serves recorded runs from bundled fixtures instead of a live backend.
// The flag lives in sessionStorage so it ends with the tab and never touches the
// visitor's saved connections, settings or thread cache.

const KEY = "10xgraph.demo"

export const SCENARIOS = ["support"]
export const DEFAULT_SCENARIO = "support"

// Used when sessionStorage is unavailable (private mode, blocked storage).
let fallback = null

export const resolveScenario = (id) =>
  SCENARIOS.includes(id) ? id : DEFAULT_SCENARIO

export const enterDemo = (id) => {
  const scenario = resolveScenario(id)
  fallback = scenario
  try {
    sessionStorage.setItem(KEY, scenario)
  } catch {
    /* the in-memory fallback keeps this page load in demo mode */
  }
  return scenario
}

export const exitDemo = () => {
  fallback = null
  try {
    sessionStorage.removeItem(KEY)
  } catch {
    /* nothing stored */
  }
}

export const activeScenario = () => {
  try {
    return sessionStorage.getItem(KEY) ?? fallback
  } catch {
    return fallback
  }
}

export const isDemoActive = () => activeScenario() !== null
```

```js
// in class DemoClient
  // Long model pauses are shortened so a replay never looks stuck.
  static MAX_GAP_MS = 1500

  async *stream() {
    const run = this.f.runs.find((r) => r.id === this.queued)
    this.queued = null
    if (!run) {
      throw new Error(
        "This is a recorded demo. Pick one of the suggested prompts, or run 10xGraph on your own agent."
      )
    }
    this.markPlayed(run.id)
    let previous = 0
    for (const { t, chunk } of run.chunks) {
      const gap = Math.min((t - previous) / this.speed, DemoClient.MAX_GAP_MS)
      previous = t
      if (gap > 0) await this.sleep(gap)
      yield structuredClone(chunk)
    }
    if (run.ended === "connection_lost") {
      throw new Error(
        "The worker process was stopped in the middle of the tool step (recorded crash)."
      )
    }
  }
```

```js
// src/lib/demo/local-search.js
// Keyword fallback for memory queries that were not recorded. The UI labels these
// results, because they are not the store's vector search.
const words = (text) => (text || "").toLowerCase().match(/[a-z0-9_]+/g) ?? []

export const searchLocally = (memories, query) => {
  const terms = [...new Set(words(query))]
  if (terms.length === 0) return []
  return memories
    .map((m) => {
      const text = words(m.content).join(" ")
      const hits = terms.filter((t) => text.includes(t.slice(0, 5))).length
      return { ...m, score: hits / terms.length }
    })
    .filter((m) => m.score > 0)
    .sort((a, b) => b.score - a.score)
}
```

### Task 11: Make replay safety visible in the product (core + API)

Today a skipped tool only writes a log line (`invoke_node_handler.py`, "already executed; replaying recorded result"). Nothing reaches the stream or the observability trace, so neither the playground nor any user's UI can show the moat. Emit a tool-result event or span attribute (for example `tool.replayed: true`) from the ledger hit, expose it in `/v1/observability`, and badge it in the Observability screen. Re-record the scenario so the demo shows the badge. **Done when:** a released `10xgraph` + `10xgraph-api` surfaces replayed tool calls, and the Observability screen marks them. Also decide whether `SqliteCheckpointer` should implement the tool ledger; POSITIONING.md currently says replay safety "requires a checkpointer", which overstates it for SQLite.

Building the demo surfaced these bugs. Fix them in this task, then re-record and restore the crash and resume chapter (the original Task 8):

| # | Package | Bug | Effect |
|---|---|---|---|
| 1 | core | The stream path (`stream_node_handler.py`, `_call_tools`) never checks or writes the tool ledger; only the invoke path does | A killed stream run re-executes tools on resume: the spike issued two refunds. Invoke mode issued one. POSITIONING.md pillar 2 is true only for invoke |
| 2 | API | A crashed run can't be resumed: empty `messages` gives 422, `resume: null` gives "Nothing to resume", and a new message gives "No tool calls to execute" and leaves the thread stuck | No supported way to finish a run the worker died in |
| 3 | core | `StreamChunk.timestamp` (`core/state/stream_chunks.py:55`) and the publisher event model (`runtime/publisher/events.py:157`) use `default_factory=datetime.now().timestamp`, which evaluates `datetime.now()` once at import | Every chunk and published event has the same timestamp, so `/v1/observability` spans are all 0 ms. Fix: `default_factory=lambda: datetime.now().timestamp()` |
| 4 | client + core | The client sends `message_id: "0"` and core keeps it | `PgCheckpointer` rejects the second thread ("Message id already belongs to another thread"). This breaks the playground on any Postgres-backed server |
| 5 | core | `QdrantStore` calls `client.search`, which `qdrant-client` 1.19 removed | Store errors on current `qdrant-client`. The demo pins 1.15.1 |
| 6 | core | `QdrantStore.aget_all` searches with an empty vector | Listing memories fails. The demo overrides it with `scroll` (`demo/agent/store.py`) |
| 7 | client + core | `searchMemory` and `memory_tool` default to different memory types (episodic vs semantic) | A memory stored with one default is invisible to a search with the other |
| 8 | core | A top-level `status` key in a tool's return value is dropped | Tool output loses data silently |
| 9 | core | `SqliteCheckpointer` has no tool ledger | Replay safety claim overstated for SQLite (see above) |
